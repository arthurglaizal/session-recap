Generate a readable recap of the current Claude Code work session.

## Scope

Cover the work done **since the last recap produced by this command in this conversation**, or otherwise **since the start of the conversation**.

If a previous recap generated by this command appears earlier in the conversation, only cover what happened after that recap.

Do not summarize the full project history, nor prior sessions that are not part of the current context.

If the session is long, adapt the granularity: group related actions into meaningful topics instead of producing an exhaustive log. Ignore trivial commands, inconsequential exploration, abandoned attempts with no impact, and low-value details.

Base everything strictly on what is actually available in the conversation. Do not invent actions, decisions, or timestamps.

## Output format

Produce exactly the following sections, in this order, in Markdown.

### `Session Summary`

Write exactly 2 sentences giving an overview of the session: the main threads of work, the most important changes or decisions, and the overall state reached by the end of the session. Do not simply repeat the table that follows.

### `Session Timeline`

Markdown table with the following columns:

`| # | Topic | What was done | Time |`

Rules:

* follow chronological order;
* start a new topic when a workstream, goal, or significant phase changes;
* adapt the number of rows to the actual density of the session; for a very long session, aim for about 8 to 12 meaningful topics;
* give each topic a short **bold** title;
* use several short bullet points in `What was done` when a topic covers multiple important actions, each prefixed with `• ` and kept on a single line;
* each bullet describes a concrete action, decision, fix, or result; avoid repetition;
* put the timestamp in the last column, in *italics*, in `HH:MM` format, corresponding to the start of the topic block;
* never invent a time if it cannot be determined reliably from the context; in that case, leave the cell empty rather than guessing.

### `Where the project stands`

Markdown table with the columns `Status | State` and exactly these three rows, in this order:

* `✅ **Done**`: what is functional, finished, validated, or stable enough;
* `🚧 **In progress**`: what has been identified but is still incomplete;
* `❓ **Open questions**`: questions, trade-offs, or choices still open.

In each `State` cell, use short bullet points, each prefixed with `• ` and kept on a single line. Only mention items that are actually relevant at the end of the session. Do not artificially fill a category if it is not relevant; use `—` instead of inventing content.

### `👉 Next step`

Outside the table, add exactly one line in this format:

`👉 **Next step**: ...`

A single sentence, indicating the most logical action to take immediately in the next session. Do not repeat the full `In progress` list.

## Language

Reply in the language the user is using in the conversation, translating the section headers and labels accordingly.

## Constraints

* Do not modify any project file: this command only produces recap text.
* Do not propose an action plan or task list beyond `Next step`.
* Never use HTML tags such as `<br>` anywhere in the output: they are not rendered in Claude Code and show up as raw text. A table cell must stay on a single line, with `• ` as the only bullet separator.
* Stay concise and directly readable in Claude Code.
